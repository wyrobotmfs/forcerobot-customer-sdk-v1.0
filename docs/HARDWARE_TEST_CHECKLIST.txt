ForceRobot 真机功能实测清单（按安全顺序）
========================================
网口示例：enP2p33s0
包目录：forcerobot-customer-sdk-v1.0
原则：一次只测一项；双手靠近急停；低速；先臂0再臂1；失败先 hold/disable。

---------------------------------------------------------------------------
0. 开测前（每次必做）
---------------------------------------------------------------------------
[ ] 急停可用，人员清场，臂下方无障碍
[ ] 确认网口：ip -br link | grep enP2p33s0
[ ] 无其它主站/程序：
      ps aux | grep -E 'runtime_dual|gravity_identify|ex_' | grep -v grep
[ ] 清锁：sudo rm -f /tmp/force_robot_sdk.lock
[ ] 只开一个入口：要么 runtime_dual，要么你的 SDK 程序（二者不能同时）

建议：前半段用 runtime_dual 手测命令；确认动作正常后再写/跑 C++ 示例。


---------------------------------------------------------------------------
1. 阶段 A — 无运动（验证总线与状态）
---------------------------------------------------------------------------
启动：
  cd forcerobot-customer-sdk-v1.0
  # 若找不到 .so：先 cp vendor/lib/libforce_robot*.so tools/
  sudo LD_LIBRARY_PATH="$PWD/tools:$PWD/vendor/lib" ./tools/runtime_dual ./config eth0

进控制台后（dual 必须带臂号 0/1）：
  0 read all
  1 read all
  0 read positions
  0 read drive_mode
  # 完整命令表见 docs/RUNTIME_COMMANDS.txt
  # 查版本用 C++ frs_version()，不要敲 version

验收：
[ ] bus ready / 从站通信正常
[ ] 两臂关节角有合理读数
[ ] 未使能时发运动应被拒绝或无效（不要强行）

退出：quit（或先 0 disable / 1 disable 再 quit）；必要时再清锁。


---------------------------------------------------------------------------
2. 阶段 B — 使能 / 下使能 / hold（小动作风险）
---------------------------------------------------------------------------
  0 enable
  0 read positions          # 或 read all
  0 hold
  0 disable

然后臂1同样测一遍：
  1 enable → 1 hold → 1 disable

验收：
[ ] enable 后 enabled_joints=7（或全轴使能）
[ ] hold 后参考冻结、不继续走目标
[ ] disable 后电机失能；臂可被（小心）扳动或显示未使能
[ ] 结果/事件有使能完成通知


---------------------------------------------------------------------------
3. 阶段 C — CSP 点到点（低速！）
---------------------------------------------------------------------------
先读当前角，再改其中 1～2 轴 ±3～5°，速度用很低值。

示例思路（命令以 help 为准，不同版本关键字可能略有差异）：
  0 enable
  0 read positions
  # 关节点到点：只动安全轴，例如 J6 ±5deg，speed 很低
  0 move joint <q1..q7> <speed> <accel>
  # 或终端若支持简写，看 help

TCP（更危险，先确认工作空间）：
  0 read ... tcp/tool pose
  # 仅沿一个方向平移 1～2cm，速度 ≤0.05 m/s

验收：
[ ] 有“已受理 / 指令完成(ARRIVED)”类结果
[ ] 实测角接近目标（自己看误差，例如 <1°）
[ ] 异常时 0 hold 能停参考；必要时急停

建议记录：目标角、速度、实测终点、是否碰撞预警空间够。


---------------------------------------------------------------------------
4. 阶段 D — 多点路径
---------------------------------------------------------------------------
停顿多点：
  两点关节路径，每点 dwell 0.5～1s，速度低

连续 blend：
  三点，中间点 blend>0，末点 blend=0
  观察中间点是否“路过不停满”

验收：
[ ] 停顿路径在点上有可见停留
[ ] blend 路径中间不停满、末点停
[ ] IK 失败会 hold/失败通知（可故意给不可达点验证一次，空间要安全）


---------------------------------------------------------------------------
5. 阶段 E — 流式跟随（stream）
---------------------------------------------------------------------------
  start joint stream → 连续更新几个目标 → finish stream

验收：
[ ] 只跟最新目标（快速连发时中间点可被跳过）
[ ] finish/hold 后停止推进
[ ] 停止更新不会自动 hold（文档语义：必须显式 finish）


---------------------------------------------------------------------------
6. 阶段 F — 工具 TCP / payload（改模型，慎动）
---------------------------------------------------------------------------
在 hold 或未使能时：
  set tcp / get tcp / clear tcp
  get payload；必要时 set payload（质量与质心）

验收：
[ ] set tcp 后 tool_pose / FK 结果变化符合预期
[ ] clear tcp 后恢复近似法兰/标定 tool
[ ] 错误时机（运动中改 tcp）应被拒绝


---------------------------------------------------------------------------
7. 阶段 G — 力控前必须 autozero
---------------------------------------------------------------------------
  0 enable
  0 autozero          # 臂静止、无外力干扰
  0 read ...          # 看 autozero_done / 外力估计是否接近 0

验收：
[ ] autozero 成功
[ ] 未 autozero 时 start drag 应拒绝（可故意测一次）


---------------------------------------------------------------------------
8. 阶段 H — CST 力控 / 阻抗（最后测，专人盯急停）
---------------------------------------------------------------------------
顺序建议：
  1) drag：轻推关节，有柔顺跟随；推完 hold/disable
  2) spring：推开后应回靠
  3) impedance_joint：小角度目标，低速
  4) impedance_tcp：小位移

验收：
[ ] 进入 CST 成功（可读 drive_mode）
[ ] 手推手感合理，无剧烈振荡
[ ] hold 能冻结；disable 能下使能
[ ] 振荡/异常立即急停，记录 cst kp/kd

本包默认参考：kp≈20，kd≈1，torque_limit=80（以 parameter.json 为准）


---------------------------------------------------------------------------
9. 阶段 I — 状态订阅 / CSV / 错误码
---------------------------------------------------------------------------
CSV：
  开采集 → 做一次短关节运动 → 停采集 → 查文件与 drop 计数

错误码：
  drive_errors @tag → 再 read drive_mode / read torques（无 read diagnostics）
  （本包不能清错；有故障用驱动器/上电流程处理）

验收：
[ ] CSV 有实测/命令位置、速度、力矩列
[ ] 订阅回调能收到状态（若用 C++ API）
[ ] 错误码 readable；无公开清错接口（预期）


---------------------------------------------------------------------------
10. 阶段 J — 离线运动学（可不上电机械，或与控制对照）
---------------------------------------------------------------------------
  ./build/ex_kinematics ./config 0
  ./build/ex_kinematics ./config 1

对照：
  真机 read 当前 q → frs_kin_fk → 与 tool_pose 比
  规划 MOVL → 再 joint_path 执行（低速）

验收：
[ ] FK 与状态 TCP 量级一致
[ ] plan_line 成功样本数 >0
[ ] 规划轨迹执行终点接近目标


---------------------------------------------------------------------------
11. 用 C++ SDK 复测（API 级）
---------------------------------------------------------------------------
先编译：
  mkdir -p build && cd build && cmake .. && cmake --build . -j

FakeBus：
  ./ex_lifecycle ../config
  ./ex_move_joint_fake ../config

真机：复制 ex_move_joint_fake.cpp → ex_move_joint_real.cpp
  改：
    opt.use_ethercat = 1;
    opt.interface_name = "enP2p33s0";
  目标角改为“当前角 ± 小增量”（先 get_state 再改）
  sudo 或 setcap 后运行
  跑完务必 disable/stop；异常清锁

按功能各写一个短程序或一个菜单程序逐项调用 frs_*，比只在控制台测更能验收客户 API。


---------------------------------------------------------------------------
12. 双臂注意
---------------------------------------------------------------------------
[ ] 臂0、臂1 分别完整走一遍 B～H（空间不干涉）
[ ] 不要期望“同时按下就完美同步”——本包不承诺原子同步
[ ] 两臂同时使能时，先确认互碰空间

---------------------------------------------------------------------------

14. 推荐一天排期
---------------------------------------------------------------------------
上午：A 总线 → B 使能 → C 低速 joint（两臂）
下午：D path → E stream → F tcp/payload → G autozero
傍晚/专人：H 力控 → I 采集 → J 运动学对照

不要一天内首次就把 drag/阻抗拉满增益。
